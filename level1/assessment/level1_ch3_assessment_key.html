📝 Notes for this chapter

This is the first variable in the course. Draw the box on the board and write a number in it; erase and rewrite as the loop runs. Fix It answer: change by was replaced with set to, so the speed is stuck at 1. If a car will not move at all, swap the batteries before you read the code — weak cells look exactly like this bug. Source: ElecFreaks wiki, Case 02 "Speed Up Gradually".

🚀 Extend — where each task goes

🟢 The wiki asks this one: make the car speed up, then slow down again, instead of dropping straight back to a crawl.
Let the speed climb as it does now → Notice what happens at the top → Decide what should change there → Make the number come back down🟡 Make the car reach full speed in exactly three seconds.
Time how long it takes now → Work out how many steps fit in three seconds → Change the step size → Test with a stopwatch🔴 Make the screen tell you which band the speed is in — slow, middling, or flat out.
Pick three icons, one per band → Decide the two numbers where the band changes → Test the speed against them as it climbs → Show the icon that matches

🧩 The blocks you need today

variables_set

Puts a value into a named box you can read again later.

let speed = 60
cuteBot.motors(speed, speed)

You see: Nothing on the screen, but the value is now stored under that name.

variables_change

Adds an amount to what is already in the variable.

let speed = 20
for (let i = 0; i < 4; i++) {
    speed += 20
    cuteBot.motors(speed, speed)
    basic.pause(500)
}
cuteBot.stopcar()

You see: The variable grows by that amount every time the block runs.

basic_forever

Everything inside runs again and again, without stopping.

basic.forever(function () {
    basic.showIcon(IconNames.Heart)
    basic.pause(500)
    basic.clearScreen()
    basic.pause(500)
})

You see: A heart that blinks on and off, about once a second, and never stops.

⚠ A forever with no pause repeats very fast. That is fine for motors (a speed ramp needs it), but a blink needs a pause to be seen.

cutebot_motors

Sets how fast each wheel turns, left and right, from -100 to 100.

cuteBot.motors(50, 25)
basic.pause(2000)
cuteBot.stopcar()

You see: The car drives in a wide curve to the right, because the left wheel is faster than the right one.

⚠ This is the most important block of the whole course. Every turn the car ever makes is two different numbers. Equal numbers go straight; a bigger left number curves right; one wheel forward and one backward spins the car on the spot; both negative backs up.

logic_if_else

Picks one of two paths, one for true and one for false.

if (cuteBot.ultrasonic(cuteBot.SonarUnit.Centimeters) < 15) {
    cuteBot.stopcar()
} else {
    cuteBot.forward()
}

You see: Exactly one of the two groups runs, never both.

logic_compare

Compares two numbers.

if (cuteBot.ultrasonic(cuteBot.SonarUnit.Centimeters) < 20) {
    cuteBot.stopcar()
}

You see: True or false, which you drop into an if block.

Talk rubric

Strong — says set replaces the value and change adds to it, and links that to why one climbs and the other does not. Developing — gets the difference but does not connect it to the car's behavior. Needs Focus — treats them as the same, or describes only one.
