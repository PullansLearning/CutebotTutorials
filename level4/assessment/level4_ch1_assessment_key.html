📝 Notes for this chapter

The wiki's question is worth real time: "why must the value be over 2cm?" Because the HC-SR04 is only trustworthy from 2cm to 400cm — below that it returns 0, and 0 would look like "very close" and trigger the turn forever. Fix It answer: only the upper bound is tested, so a 0 reading counts as an obstacle and the car spins on the spot. If a car will not move at all, swap the batteries before you read the code — weak cells can stop a car completely. Source: ElecFreaks wiki, Case 09 "Autonomous Obstacle Avoidance".

🧩 The blocks you need today

cutebot_ultrasonic

Measures how far away the thing in front of the car is.

basic.forever(function () {
    basic.showNumber(cuteBot.ultrasonic(cuteBot.SonarUnit.Centimeters))
    basic.pause(500)
})

You see: A number in centimeters or inches — the sonar reads from 2 cm to 400 cm.

logic_and

True only when both tests are true.

if (input.buttonIsPressed(Button.A) && input.buttonIsPressed(Button.B)) {
    cuteBot.stopcar()
}

You see: True or false for the pair of tests together.

Talk rubric

Strong — says a single test lets untrustworthy readings near zero count as obstacles, so the lower end throws out noise and only real, in-range measurements trigger the turn. Developing — mentions the second test but not what it protects against. Needs Focus — says one test is enough, or describes the upper end only.
