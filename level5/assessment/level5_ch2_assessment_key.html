📝 Notes for this chapter

Two boards again. The division by 10 is the whole trick: tilt comes back in milli-g, roughly -1024 to 1024, and wheel speed only goes to 100. Last chapter's rule still holds — a number means nothing until the car decides — but now the agreement also fixes the scale: divide by 10, and what arrives is already a wheel speed. Pairs keep their own group numbers; the 1 in the code is the wiki's. MakeCode links — remote _Pv01m2ehfcKT, car _VYxbiCVtE962. Fix It answer: the raw tilt is sent without dividing, so the wheels sit at full speed for almost any lean and steering disappears. 🧩 The blocks you need today

input_acceleration

Reads the pull on the micro:bit along one axis — tilt it and the number changes.

basic.showNumber(input.acceleration(Dimension.X))

You see: About 0 when it lies still and flat, and about 1000 straight down.

radio_send_value

Sends a name and a number together.

radio.setGroup(7)
radio.sendValue("speed", 80)

You see: The other micro:bit receives both parts in one message.

radio_on_value

Runs the blocks inside when a name and number arrive together.

radio.setGroup(7)
radio.onReceivedValue(function (name, value) {
    if (name == "speed") {
        cuteBot.motors(value, value)
    }
})

You see: Nothing until a message comes in, then the blocks inside run.

math_arithmetic

Adds, subtracts, multiplies, or divides two numbers.

basic.showNumber(20 + 22)

You see: One number, which you drop into another block.

Talk rubric

Strong — says y carries forward/back and x carries the side lean, and mixing them (sum for one wheel, difference for the other) turns two tilts into two wheel speeds. Developing — says both are needed without explaining how they combine. Needs Focus — treats x and y as separate cars or separate commands.
